Misión: no perder nunca tu código

Git guarda el historial de cambios de tu proyecto, como los puntos de guardado de un videojuego: si algo sale mal, regresas a una versión anterior. Casi todos los equipos de desarrollo lo usan.

Git y GitHub: no son lo mismo
Git
Es la herramienta que vive en tu computadora. Guarda el historial de cambios de un proyecto y funciona sin internet. Fue creada por Linus Torvalds en 2005 para desarrollar el kernel de Linux.
GitHub
Es la plataforma en la nube donde se alojan los repositorios de Git. Permite compartir código, revisar cambios con pull requests, gestionar tareas y publicar sitios con GitHub Pages.
El viaje de un cambio: 4 etapas
1
Directorio de trabajo
Editas y creas archivos en tu proyecto.
2
Área de preparación
git add elige qué cambios irán en la siguiente versión.
3
Repositorio local
git commit guarda esa versión en tu computadora.
4
Repositorio remoto
git push sube la versión a GitHub para compartirla.
Un poco de historia
2005
Linus Torvalds crea Git para organizar el desarrollo del kernel de Linux.
2008
Nace GitHub, una plataforma para alojar y compartir repositorios Git.
2018
Microsoft adquiere GitHub, que hoy es uno de los lugares donde más se comparte código.

Tu inventario de comandos

Los nueve comandos que más usamos, con un ejemplo de cada uno.

git init
Crea un repositorio nuevo en la carpeta actual.
$ git init
git clone
Copia un repositorio de GitHub a tu computadora.
$ git clone URL-del-repo
git status
Muestra qué archivos cambiaron y cuáles están listos.
$ git status
git add
Prepara los cambios para el siguiente commit.
$ git add .
git commit
Guarda los cambios con un mensaje descriptivo.
$ git commit -m "Agrega login"
git push
Sube tus commits al repositorio remoto.
$ git push origin main
git pull
Descarga y une los cambios de tus compañeros.
$ git pull origin main
git branch / switch
Crea una rama o cambia de una a otra.
$ git switch -c nueva-funcion
git merge
Une los cambios de una rama con otra.
$ git merge nueva-funcion

Ramas: trabajar sin romper nada

Una rama es una línea paralela del proyecto. Cada integrante trabaja su parte en su propia rama y, cuando está lista, se une a la rama principal (main). Pruébalo en el simulador.

Rama actual: main
$ git init
Flujo de trabajo en equipo con GitHub
1
Clonar
Copias el repositorio del equipo con git clone.
2
Crear una rama
Una rama por tarea: git switch -c mi-tarea.
3
Hacer commits
Guardas tu avance con git add y git commit.
4
Subir cambios
Envías tu rama a GitHub con git push.
5
Pull request
Pides que el equipo revise y apruebe tus cambios.
6
Revisar y fusionar
Se unen a main y todos descargan con git pull.
Errores comunes y cómo evitarlos
Conflictos de fusión
Ocurren cuando dos personas editan la misma línea. Git marca ambas versiones y el equipo decide cuál conservar.
Subir datos sensibles
Contraseñas y llaves nunca deben subirse. Se evitan con un archivo .gitignore.
Trabajar directo en main
Es mejor crear una rama y fusionarla con un pull request revisado.

Buenas prácticas

Hábitos que hacen más fácil trabajar con Git en equipo.

Haz commits pequeños y frecuentes.
Escribe mensajes claros que expliquen qué cambió.
Haz git pull antes de empezar a trabajar y antes de hacer push.
Usa una rama por cada tarea o función nueva.
Agrega un .gitignore y un README a cada proyecto.
